# Existing BookshelfNG auxiliary databases

These SQL files retain the schema and `VersionInfo` rows from a healthy, stopped
BookshelfNG `0.4.21.76` instance using the repository's synthetic schema-158 main
fixture. All other rows were omitted. `manifest.json` records the exact public
source archive and SQL checksums. No operator data or credentials are present.

The public Linux x86 `.76` archive failed while creating a new log database:
FluentMigrator's `GenericProcessorBase.CreateCommand` threw a null-reference
exception while recording migration 33. Its main database was already at 158.
The same unchanged archive starts successfully with the existing schema-158
auxiliary databases generated by the healthy musl x64 predecessor. SQLite data
is architecture-independent.

Only the x86 installed handoff explicitly enables
`--preinitialized-source-auxiliary-databases`. Its result records this choice.
The other platforms continue exercising fresh auxiliary-database creation. This
is an existing-installation migration baseline; it does not waive or repair the
predecessor's fresh-log failure. Keep the original failed-run evidence.
